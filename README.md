# Browser Test Workbench

AI와 함께 작성한 Playwright 웹 테스트를 각자의 PC에서 실행하고, 진행 단계와 결과를 확인하는 로컬 작업대입니다.

- 평소 쓰는 AI가 테스트 코드 작성과 분석을 돕습니다. 작업대는 Playwright로 테스트를 실행하고 이력·보고서·캡처를 보여 줍니다. 작업대에 AI 모델이나 API 키를 설정할 필요는 없습니다.
- 실행 기록과 설정은 각 PC에 저장합니다. Obsidian 내보내기는 선택 사항입니다.
- 현재 **macOS Chromium**에서 설치와 실행을 확인했습니다. Windows 설치와 실행은 실기기 검증이 필요합니다.

## 처음 사용하기

### 1. 준비하고 설치하기

1. Python **3.9 이상**과 Node.js **20 이상**을 설치합니다. Windows에서는 Python 설치 시 `py` 실행기도 설치합니다.
2. 저장소를 내려받아 압축을 풀거나 Git으로 복제합니다.
   ```sh
   git clone https://github.com/straycat405/browser-test-workbench.git
   ```
3. 내려받은 폴더에서 운영체제에 맞는 설치 파일을 실행합니다.
   - Windows: `setup-windows.bat`
   - macOS: `setup-macos.command`
4. 설치가 끝나면 작업대가 열립니다. 브라우저가 열리지 않으면 `http://127.0.0.1:7790`에 접속합니다.

설치 파일은 npm 패키지와 Playwright Chromium을 내려받으므로 인터넷 연결이 필요합니다. macOS에서 실행 권한 오류가 나면 터미널에서 내려받은 폴더로 이동해 다음 명령을 실행합니다.

```sh
chmod +x setup-macos.command start-macos.command
```

### 2. 예제 테스트 실행하기

1. 처음 시작 화면에서 **기존 테스트 실행**을 고르고 **설정 저장**을 누릅니다. 기본 경로는 예제 폴더입니다.
2. 작업대에서 **예제 실행**을 누릅니다. 예제 페이지는 인터넷 연결 없이 열립니다.
3. **실행 기록**에서 방금 실행한 항목의 **성공** 상태를 확인합니다.
4. **보고서**에서 실행 단계와 캡처를 확인합니다. 캡처는 클릭해서 확대하고 바깥 영역·×·Esc로 닫습니다.

보고서의 **실행 조건**에는 실행에 사용한 테스트 폴더 또는 설정 파일, 확인 가능한 Git 브랜치·커밋과 작업 트리 상태가 표시됩니다. Playwright가 실행을 시작하면 프로젝트에 설정된 브라우저와 기준 URL의 스킴·호스트·포트도 표시됩니다.

다음부터는 Windows에서 `start-windows.bat`, macOS에서 `start-macos.command`를 실행해 작업대를 엽니다.

## AI로 내 테스트 만들기

1. 첫 설정에서 **AI로 테스트 만들기**를 선택합니다. 이미 설정했다면 상단 **AI 테스트 안내**를 엽니다. 기본 예제 폴더를 쓰는 경우 **개인 폴더로 바꾸기**를 선택할 수 있습니다.
2. **요청문 복사**를 누르고 평소 쓰는 AI에 붙여 넣습니다. 대괄호 안에 테스트할 주소·동작·기대 결과를 채웁니다.
3. 파일을 다룰 수 있는 AI에는 안내된 테스트 폴더를 열어 파일 작성을 요청합니다. 채팅형 AI를 쓴다면 답변의 코드를 복사해 해당 폴더에 `first-test.spec.js`로 저장합니다.
4. 작업대에서 **폴더 내 테스트 실행**을 누릅니다. 결과는 **실행 기록**에서 확인합니다.

테스트 폴더가 비어 있으면 실행 버튼이 비활성화됩니다. 파일을 저장한 뒤 다시 실행하세요. `examples/example.spec.js`에서 `@playwright/test`, `test.step`, 화면 캡처 작성 예시를 볼 수 있습니다.

## 기존 테스트 실행하기

1. **설정 → 폴더 선택**에서 테스트 파일이 들어 있는 폴더를 고르고 설정을 저장합니다.
2. **폴더 내 테스트 실행**을 누릅니다. 선택한 폴더의 테스트 전체가 실행됩니다.
3. 실행 중 중단하려면 **실행 중단**을 누릅니다. 종료 후 이력에 **중단**으로 표시됩니다. 중단 전에 웹 화면에서 이미 저장된 데이터는 그대로 남습니다.

프로젝트 자체 설정을 쓰려면 **설정 → 프로젝트의 Playwright 설정 사용**을 선택하고 설정 파일의 전체 경로를 입력합니다. 설정 파일에 지정된 테스트 전체와 브라우저 설정을 사용합니다. 테스트 결과 파일 경로는 작업대의 개인 데이터 폴더로 지정되며 프로젝트의 기존 리포터도 실행됩니다. 프로젝트에 필요한 패키지·환경 변수·인증 파일은 해당 프로젝트에 준비해야 합니다. **예제 실행**은 작업대 기본 설정을 사용합니다.

기본 설치는 Chromium을 준비합니다. Firefox 또는 WebKit을 사용하려면 작업대 폴더에서 각각 `npx playwright install firefox` 또는 `npx playwright install webkit`을 실행하세요.

기존 `playwright-cli run-code` 시나리오는 별도 연동이 필요합니다. 아래 방법으로 기존 실행 기록은 가져올 수 있습니다.

## 기존 실행 기록 가져오기

1. 상단 **기존 기록 가져오기**를 누릅니다.
2. 기존 도구의 폴더 또는 그 안의 `out` 폴더 경로를 입력합니다. `out/실행별 폴더/result.json`과 선택적인 `dashboard/events.jsonl` 형식을 지원합니다.
3. **기록 가져오기**를 누릅니다. 이벤트 로그가 있는 중단 기록도 가져오며, 이미 가져온 기록은 건너뜁니다.

원본은 그대로 두고 보고서·캡처·엑셀을 이 PC의 작업대 데이터 폴더에 복사합니다. **보고서**에서 기존 상세 기록을 볼 수 있습니다. 실행 로그에 콘솔 출력이 없으면 저장된 실행 단계를 표시합니다.

## Obsidian 내보내기

기본값은 꺼짐입니다. 사용하려면 **설정 → Obsidian으로 결과 내보내기 사용**을 켜고 볼트 안의 기존 폴더를 입력하세요. 실행 기록을 선택하고 **Obsidian으로 내보내기**를 누를 때 보고서와 결과 파일이 복사됩니다.

## 문제 해결

- **설치 파일이 실패합니다.** Python·Node.js 버전을 확인하세요. 설치 파일을 다시 실행하거나 작업대 폴더에서 `npm ci`, `npx playwright install chromium`을 차례로 실행합니다.
- **작업대가 열리지 않습니다.** 실행 창이 열려 있는지 확인하고 `http://127.0.0.1:7790`을 직접 엽니다. 포트가 사용 중이면 서버 실행 전 `BTW_PORT` 환경 변수로 다른 포트를 지정합니다.
- **실행 버튼이 비활성화됩니다.** 설정을 저장했는지, 선택한 폴더에 Playwright 테스트 파일이 있는지 확인합니다. 진행 중인 테스트가 있다면 종료를 기다립니다.
- **테스트가 실패합니다.** 해당 실행을 선택해 실패 단계와 **실행 로그**를 확인합니다. 프로젝트 설정을 사용하는 경우 필요한 패키지와 환경 변수도 확인합니다.
- **실패 당시 화면이나 네트워크 요청을 확인하고 싶습니다.** 작업대 기본 설정은 실패 시 Playwright 트레이스를 저장합니다. 보고서의 **트레이스 다운로드** 링크에서 ZIP 파일을 받아 `npx playwright show-trace <파일>`로 엽니다. 프로젝트 자체 설정을 쓰는 경우 그 프로젝트의 트레이스 설정이 적용됩니다.

## 데이터와 개발 검증

설정·실행 기록·캡처·로그는 Windows의 `%LOCALAPPDATA%\BrowserTestWorkbench`, macOS의 `~/Library/Application Support/BrowserTestWorkbench`에 저장합니다. `BTW_DATA_DIR` 환경 변수로 위치를 바꿀 수 있습니다. 서버는 `127.0.0.1`에서 실행됩니다.

테스트와 결과에는 계정 정보나 업무 데이터가 포함될 수 있습니다. 공유 전 개인 테스트 파일과 결과물을 확인하세요. `.gitignore`는 흔한 인증 파일과 결과물을 제외합니다.

개발 검증은 `npm ci`와 `npx playwright install chromium`을 실행한 뒤 다음 명령으로 수행합니다.

```sh
python -m unittest discover -s tests -v
```

GitHub Actions에는 Windows·macOS 검증이 설정되어 있습니다. Windows 실기기 검증은 아직 완료하지 않았습니다.
